## 2. Как это устроено сейчас

**Гость (работает).** Клиент при старте (`src/App.tsx:62` → `fetchBalance`) вызывает `POST /api/user/register`. Сервер создаёт пользователя, отдаёт токен (32 случайных байта) и 15 000 бесплатных символов. В базе лежит только sha256 токена (`server/src/db.ts:133`, `server/src/postgresDb.ts:63`). Клиент хранит токен в localStorage (`src/store/userStore.ts:90`). Каждый запрос идёт с `Authorization: Bearer <токен>`, `requireAuth` ищет пользователя по хэшу (`server/src/middleware.ts:41`).

**Вход по email и паролю (только клиент).** `AuthModal.tsx`, `account.ts`, `serverApi.ts`, `clientCrypto.ts`. Сервера для этого нет.

**Деньги.** Баланс в символах. Списание до синтеза одним атомарным `UPDATE … WHERE balance >= $2`, при ошибке возврат (`tts.ts:72`). Пополнение через ЮKassa: пакеты и цены зашиты на сервере (`payment.ts:7`), после оплаты приходит вебхук; сервер не верит его телу, сам спрашивает у ЮKassa статус и сумму и начисляет один раз (`yookassa.ts:110`, `postgresDb.ts:213`).

**Озвучка.** Клиент шлёт `POST /api/tts/stream` без `provider`; сервер ищет провайдера по голосу (`tts.ts:47`) среди Gemini, OpenAI, ElevenLabs, OpenRouter и Edge (неофициальный бесплатный вход Microsoft).

**База.** Сервер: PostgreSQL, если задан `DATABASE_URL`, иначе JSON-файлы. Две таблицы: `users`, `payments`. Клиент: IndexedDB (Dexie) для книг, страниц PDF и кэша озвучки; настройки и сессия в localStorage.

**Развёртывание.** Traefik → nginx (сайт + прокси `/api`) → Node/Express → Postgres.

**3. Сервер падает целиком при сбое базы.** 🔬 (+📖 для пункта в)
- Где: (а) `middleware.ts:41-53`: `requireAuth` это `async` без `try/catch`, а в Express 4 отклонённое обещание не попадает в обработчик ошибок. Так же `routes/user.ts:17` (регистрация), `routes/payment.ts:61` и возврат символов внутри `catch` в `routes/tts.ts:107`. (б) `postgresDb.ts:26`: `initPromise` создаётся в конструкторе, и никто на него не подписан. (в) `postgresDb.ts:17-24`: у пула нет `pool.on('error')`.
- Как ломается: (а) база моргнула во время запроса с токеном → процесс завершился с кодом 1, запрос остался без ответа (эксперимент 2). (б) сервер стартовал раньше базы → процесс падает при старте (эксперимент 3). (в) база перезапустилась → пул шлёт событие `error` без слушателя → падение (по документации `pg`, без запуска).
- Побочный эффект: запросы озвучки «в полёте» уже списаны и не возвращены. То же при деплое: `index.ts:19-23` на SIGTERM сразу делает `process.exit`, не дождавшись активных запросов.
- Что делать: `try/catch` с ответом 503 в `requireAuth`, `register`, `confirm-mock`; `initPromise.catch(...)` с повтором подключения; `pool.on('error', …)`; `process.on('unhandledRejection')` как последний рубеж; на SIGTERM дожидаться активных запросов. Сейчас спасает только `restart: unless-stopped`.

### P1 — важно

**4. На сервере нет авторизации по email.** 🔬
- Клиент вызывает: `POST /api/auth/register|login|refresh|forgot-password`, `POST /api/user/sync`, `GET|POST /api/user/keys` (`src/infra/serverApi.ts:123-352`). Сервер на все отвечает 404 (HTML, не JSON), эксперимент 1. В `server/node_modules` нет ни bcrypt/argon2, ни jwt, ни почтовой библиотеки.

**5. Любой 401 при озвучке заменяет аккаунт новым гостем.** 🔬

После появления входа: токен истёк во время чтения → аккаунт стёрт из клиента. Озвучка должна идти через `withAuth` (`account.ts:50`), а не через свою копию логики.

**6. Цена символа одна для всех провайдеров, и она ниже себестоимости.** 📖 (цены провайдеров по публичным прайсам)

При курсе порядка 80–100 ₽ за доллар (проверьте свой) OpenAI выходит в 1,2–1,5 ₽ за 1000, то есть в 1,6–3,8 раза дороже цены пакета (зависит от пакета и курса); ElevenLabs в 10–25 раз.

### P2 — починить или продумать до написания серверной части входа

**10. Облачная копия API-ключей.** 📖
- Пароль и логин, и ключ шифрования (`account.ts:240`, `clientCrypto.ts:46-76`). Сервер видит пароль при входе и может расшифровать копию: «шифрование на клиенте» не защищает от самого сервера. Нужны два независимых ключа (для входа и для хранилища) или отдельная фраза.
- PBKDF2 на 100 000 кругов; текущая рекомендация OWASP для SHA-256 — 600 000.
- Копия пишется только при регистрации (`account.ts:185`), позже изменённые ключи на сервер не попадают. При входе старая копия **перезаписывает** локальные ключи (`settings.ts:324-335`).
- Смена или сброс пароля делает копию нечитаемой, а при входе ошибка расшифровки только пишется в консоль (`account.ts:148-151`).
- Баннер «безопасно сохранять в зашифрованном виде (AES-256)» (`SettingsModal.tsx:366`) вводит в заблуждение: локально ключи у всех лежат в открытом виде в localStorage.

**11. Синхронизация слепо применяет ответ сервера.** 🔬

**14. Бесплатные символы и регистрация при запуске.** 📖
- Каждый посетитель получает аккаунт и 15 000 символов, даже не открыв облако (`App.tsx:62`). Защита только лимит по IP; когда он заработает (п.2), его обходят IPv6 и VPN. Потолка расходов на платных провайдерах нет.
- Что делать: регистрировать при первом облачном запросе; бонус выдавать после подтверждения email; поставить лимиты расходов у провайдеров.
- Гость может **платить**, а его токен единственный ключ к купленному балансу: очистка данных браузера или переустановка приложения = потеря денег без возврата. Схема Block Map требует вход для облака; код этого не делает. Минимум: просить вход перед первой оплатой.

**15. PDF-эндпоинт принимает тело до 50 МБ от любого гостя.** 📖
- `app.ts:48-54`: после проверки токена Express целиком читает и разбирает JSON до 50 МБ (6 раз в минуту на пользователя). Гостевой токен бесплатный, так что желающий кладёт сервер несколькими аккаунтами (разбор JSON такого размера занимает процессор, а процесс однопоточный). У Gemini для inline-данных свой предел (раньше 20 МБ, проверьте актуальное значение), так что 50 МБ скорее всего не нужны.
- Что делать: лимит по реальной необходимости (например 20–25 МБ), одновременно не больше 1–2 таких запросов, OCR только для подтверждённых аккаунтов.

**16. Отмена запроса клиентом = потеря символов.** 📖

**18. Список голосов запрашивается на каждую фразу.** 📖

#### Клиентская база (IndexedDB, Dexie)

Схема в порядке (п. «Что сделано хорошо»), проблемы в росте данных и в тихих сбоях.

**21. Аудиокэш растёт без предела и не чистится.** 📖

- Итог: правки пользователя и распознанные страницы (в том числе оплаченные в Gemini) пропадают молча, после перезапуска распознаются и оплачиваются заново.

**23. Скорость Edge применяется дважды, а кэш про неё не знает.** 📖
- Ключ кэша не содержит `speed` и `pitch` (`cacheKey.ts:12-22`). Клиентский Edge (`edgeTts.ts:54-62`) и серверный Edge (`cloudTts.ts:93-98` → `edge.ts:97-113`) вшивают скорость в звук, а плеер ставит ещё и `playbackRate` (`audioManager.ts:151,180` → `htmlAudioPlayer.ts:41`).
- Итог: Edge на скорости 1.5 звучит примерно в 2,25 раза быстрее нормы; после смены скорости старые фразы из кэша идут со старой, новые с новой. Для OpenAI и OpenRouter скорость в запрос не уходит, там всё верно.
- Что делать: не передавать `speed`/`pitch` в Edge и облако (скорость делает плеер) либо добавить их в ключ.

**24. Синхронизация позиций чтения небезопасна по логике.** 📖 (серверного маршрута нет, п.4)
- `bookPosition.ts:337-349`: серверная позиция применяется без сравнения времени; числа проверяются только через `typeof` (проходят NaN, минус, страница больше числа страниц); глава игнорируется; запись идёт прямо в стор мимо `writePosition`, в базу не сохраняется. Пустой элемент в ответе при открытой книге даёт `TypeError`.

- Id книги случайный при каждом импорте (`createPagedBook.ts:19-21` и все парсеры), так что одна и та же книга на двух устройствах получит разные id и сопоставить их не по чему. Нужен стабильный id (хэш файла).
- Что делать: применять только более новую позицию, проверять главу, предложение и страницу по открытой книге, писать через `writePosition`.

**25. Удаление книги не атомарно, остаются «хвосты».** 📖
- `library.ts:489-496`: книга и PDF удаляются в одной транзакции, страницы и аудиокэш отдельными вызовами после неё; список обновляется только в конце (`:502`). Если один из шагов упадёт, данные удалены наполовину, а в списке книга остаётся («Книга не найдена»).
- `pagedSession.ts`: запись страниц (`:189`) и статусов ошибок (`:213`) не проверяет флаг `disposed` (он проверяется только в таймерах), поэтому распознавание, запущенное до удаления, дописывает страницы удалённой книги, и они уже не удалятся. Очистки «сирот» при старте нет.
- Что делать: одна транзакция по `books`, `pdfFiles`, `pdfPages`, `audioCache`; проверка `disposed` перед записью; зачистка сирот при старте.

**26. Книга хранится одним большим объектом.** 📖
- `library.ts:74`: `db.books.update` переписывает запись целиком (все главы; у PDF «целиком» ещё и сам файл, `:375`), с задержкой 600 мс после каждого шага чтения (`:48`). `db.books.each` читает все книги целиком при старте и после каждого закрытия, импорта, удаления.
- Итог: PDF на 100 МБ в режиме «целиком» значит, что позиция каждые несколько секунд перезаписывает 100 МБ; библиотека из 30 текстовых книг по 3 МБ читает около 100 МБ при каждом возврате.
- Что делать: позицию вынести в маленькую отдельную таблицу, главы и PDF хранить отдельно от метаданных.

## 6. Что сделано хорошо

- Токены: 256 бит случайности, в базе только sha256, длина проверяется.
- Все SQL-запросы с параметрами, инъекций не нашёл.
- Деньги: списание атомарное, возврат ровно один на одно списание, начисление один раз (`WHERE status='pending'` в транзакции), вебхук не верит телу и сверяет сумму, пакеты зашиты на сервере, адрес возврата фильтруется по списку (есть тест).
- `confirm-mock` закрыт при настроенной ЮKassa и в production (в двух местах).
- Ключи провайдеров только в заголовках, не в URL и не в логах; SSRF нет (адреса провайдеров зашиты, `model` из тела не читается); текст для Edge экранируется.
- Лимиты на озвучку (60/мин) и PDF (6/мин) по пользователю; большой JSON (50 МБ) только после проверки токена.
- CORS по списку и без cookie, значит CSRF нет.
- Tauri: адрес прокси проверяется строго, PDF-обработчик работает через непрозрачные идентификаторы, есть лимиты размера и таймауты, временные файлы чистятся.
- В клиенте нет `innerHTML`/`eval`.
- Клиентская база: схема Dexie v1→v2 только добавляет таблицы, данные не трогает; постраничный импорт PDF пишет книгу и файл одной транзакцией; запись позиции идёт с задержкой, по очереди и сбрасывается при скрытии вкладки, закрытии, импорте, удалении (`library.ts:48-95`); ключ аудиокэша не содержит ключей API, токена и адреса сервера; ответ сервера не может создать или удалить книги.
- `strict: true` в обоих проектах, зелёные тесты, чистые типы, 0 уязвимостей в зависимостях.
